# 支付服务超时处理 Runbook

## 适用场景

当用户提交订单后，支付服务响应超过 3 秒，或者订单结算接口出现 timeout、gateway timeout、read timed out 等错误时，适用本 Runbook。

## 常见原因

1. 第三方支付网关响应变慢。
2. payment-service 连接池耗尽。
3. order-service 调用 payment-service 的超时时间设置过短。
4. Redis 缓存不可用导致支付前置校验变慢。
5. 数据库慢查询拖慢订单结算链路。

## 排查步骤

1. 查看 payment-service 的错误日志，确认是否出现 timeout 或 gateway timeout。
2. 查看 payment-service 的 P95/P99 延迟指标。
3. 查看链路追踪中 payment-gateway span 的耗时和状态。
4. 检查最近是否有支付服务、网关配置或订单服务发布。
5. 如果第三方网关异常，切换备用支付通道或开启支付降级策略。

## 修复建议

1. 临时提高支付调用超时时间，但需要避免无限等待。
2. 启用备用支付通道。
3. 对支付结果使用异步补偿机制。
4. 对订单结算接口增加熔断和降级。
5. 通知第三方支付服务商确认网关状态。

## 风险提示

不要直接重启所有支付实例。重启可能导致正在处理中的支付请求丢失，应优先确认是否存在消息补偿或幂等处理。
