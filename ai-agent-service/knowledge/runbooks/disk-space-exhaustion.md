# 磁盘空间耗尽处理 Runbook

## 适用场景

当主机、容器可写层或持久卷接近满容量，导致日志、临时文件、数据库或应用写入失败时，适用本 Runbook。常见日志关键词包括 `No space left on device`、`ENOSPC`、`Disk quota exceeded`、`Read-only file system`、`cannot write`、`磁盘空间不足`、`inode exhausted`；常见指标包括 `node_filesystem_avail_bytes`、`node_filesystem_files_free`、`kubelet_volume_stats_available_bytes`、filesystem usage、inode usage、disk I/O latency 和 log write error count；Trace 中可能出现文件、数据库或对象落盘 span 失败，错误码为 ENOSPC，或者写入相关 span 延迟显著升高。

容量百分比高并不总是故障，Trace 延迟也不能单独证明空间耗尽。更明确的证据是目标挂载点的可用字节或 inode 接近零，并且应用在同一文件系统上出现 ENOSPC、只读挂载或写入失败。

## 常见原因

1. 应用日志没有轮转，错误风暴导致日志文件快速增长。
2. 临时文件、上传文件、缓存、heap dump、core dump 或诊断文件未清理。
3. 数据库数据、WAL/binlog、消息存储或备份增长超过容量规划。
4. 容器镜像、可写层或未回收卷占用节点空间。
5. 大量小文件耗尽 inode，即使仍有可用字节也无法创建新文件。
6. 文件已删除但仍被进程打开，空间没有实际释放。

## 排查步骤

1. 确认报错进程实际写入的挂载点，使用 `df -h` 检查容量、`df -i` 检查 inode，避免只查看主机根分区而遗漏容器卷或独立 PVC。
2. 使用 `du -x -h -d 1 <mount>` 从目标挂载点逐层定位大目录，记录异常增长路径；不要跨文件系统执行无边界扫描。
3. 检查日志增长速率、轮转状态、临时目录、上传目录、dump 文件和最近异常风暴，确认哪个进程仍在写入。
4. 使用 `lsof +L1` 检查已删除但仍被进程持有的文件；确认进程安全重载或重启后空间才会释放。
5. 数据库或消息存储目录增长时，检查保留策略、复制状态、归档、WAL/binlog 和备份任务，由对应存储负责人确认哪些数据可处理。
6. 对齐 `node_filesystem_avail_bytes`、inode、写入速率、I/O 延迟和发布记录，估算剩余时间并判断是否需要立即止损。

## 处理建议

1. 先限制异常日志、上传、批任务或 dump 的继续增长，保留必要样本后再处理存量文件。
2. 按已批准的保留策略轮转、压缩或清理明确可再生的日志、临时文件和缓存，并在每一步后验证可用空间。
3. 空间无法安全释放时扩容对应磁盘或持久卷，同时确认文件系统扩展步骤、配额和监控阈值。
4. 对持有已删除大文件的进程执行受控 reload 或滚动重启，确保服务容量和数据写入安全。
5. 修复日志轮转、保留周期、容量预测和分级告警；恢复后验证写入成功、文件系统可写、inode 充足且增长速率回归正常。

## 风险提示

不得直接删除数据库数据文件、WAL/binlog、消息队列存储、容器运行时目录或来源不明的大文件，这可能造成数据损坏、无法恢复或审计证据丢失。删除仍被进程打开的文件不会立即释放空间。清理和重启前应确认备份、复制、保留策略、目标挂载点及回滚方案，并避免诊断扫描进一步加重磁盘 I/O。
