# 学习地图

你不需要在开始前掌握很深的 SRE 或 AI Agent 知识。这个项目的学习方式是：只学项目真正用得到的内容，并且按 MVP、增强版、冲刺版逐步加深。

## 学习主线

这个项目的学习优先级是：

```text
Java 后端工程能力 > AI Agent 落地能力 > SRE 可观测性知识 > 部署和展示能力
```

后端是主线，AI 是增强点。面试时要能讲清楚：AI 服务不是孤立脚本，而是被后端任务系统、工具网关、审计、限流和可观测性管理起来。

## MVP 必学

### Spring Boot 分层架构

要能回答：

- Controller、Service、Repository 分别负责什么？
- 为什么 DTO 和 Entity 要分开？
- 为什么 `fault` 模块通过 `IncidentService` 创建故障，而不是直接操作数据库？

项目中的用法：

- 故障事件管理。
- 故障注入。
- 观测数据查询。
- 诊断报告保存。

### 日志、指标、链路追踪

日志要能回答：

- 发生了什么？
- 哪个服务报错了？
- 出现了什么错误信息或异常？

指标要能回答：

- 接口延迟是否升高？
- 错误率是否升高？
- CPU、内存或连接池是否异常？

链路追踪要能回答：

- 哪个服务调用最慢？
- 哪个下游服务导致请求失败？
- 一个请求经过了哪些服务？

项目中的用法：

- 为每个故障场景准备模拟日志、指标和 trace。
- 让 AI 基于这些证据生成诊断报告。

### Python AI 服务调用

要能回答：

- 为什么 Java 后端不直接写全部 AI 逻辑？
- Spring Boot 如何调用 Python FastAPI？
- AI 服务返回结构化 JSON 有什么好处？

项目中的用法：

- Spring Boot 负责业务状态。
- Python 服务负责 Prompt、RAG、工具调用和报告生成。
- 最终报告必须带根因、证据、建议和置信度。

### RAG 基础

要能回答：

- RAG 的流程是什么？
- 为什么企业 AI 应用需要私有知识库？
- 如何让报告引用 Runbook 来源？

项目中的用法：

- 把运维手册写入 Chroma。
- 根据故障现象检索相关 Runbook。
- 把检索结果作为诊断证据。

## 增强版必学

### 异步任务

要能回答：

- 为什么 AI 诊断不适合一直阻塞 HTTP 请求？
- 任务状态机如何设计？
- 任务失败、重试和取消怎么处理？

项目中的用法：

- 创建诊断任务后立即返回 `taskId`。
- 后台执行 AI 诊断。
- 前端查询或订阅任务状态。

### SSE 实时推送

要能回答：

- SSE 和 WebSocket 的区别是什么？
- 为什么 AI 诊断过程适合用 SSE？
- 页面刷新后如何恢复任务状态？

项目中的用法：

- 实时展示“查询日志、查询指标、检索 Runbook、生成报告”等步骤。
- 让 Agent 过程透明化。

### Function Calling 和工具网关

要能回答：

- Function Calling 解决什么问题？
- 为什么不能让模型直接访问数据库？
- 工具调用为什么要审计？

项目中的用法：

- 当前由确定性诊断工作流选择工具，未来可替换为模型自主选择。
- Spring Boot Tool Gateway 统一执行工具。
- 工具调用记录入库，前端展示调用时间线。

### Redis 工程化

要能回答：

- Redis 在项目里具体解决了哪些问题？
- 缓存、限流、任务状态、Stream 分别适合什么场景？
- AI 应用为什么特别需要限流和缓存？

项目中的用法：

- 缓存重复诊断结果。
- 限制频繁诊断请求。
- 存储诊断任务状态。
- 对重复故障分析进行去重。
- 可选使用 Redis Stream 保存诊断过程事件。

### Resilience4j

要能回答：

- 超时、重试、熔断、限流分别解决什么问题？
- 为什么重试可能放大故障？
- AI 服务不可用时系统如何降级？

项目中的用法：

- 保护 Spring Boot 调用 Python AI 服务。
- 保护 AI 服务调用 Chroma 或模型接口。
- 避免下游异常拖垮主后端。

## 冲刺版进阶

### Prometheus 和 Grafana

要能回答：

- 系统应该暴露哪些指标？
- 诊断任务成功率、失败率、耗时有什么价值？
- AI 调用延迟和失败率为什么需要监控？

项目中的用法：

- 暴露 Spring Boot Actuator 指标。
- 用 Prometheus 采集。
- 用 Grafana 展示任务、接口和 AI 调用状态。

### OpenTelemetry

要能回答：

- TraceId 的作用是什么？
- 日志、任务、工具调用如何关联？
- 跨服务排查问题为什么需要链路追踪？

项目中的用法：

- `HTTP 请求 -> 诊断任务 -> 工具调用 -> AI 服务调用 -> 诊断报告` 全链路关联。

### AI 评测

要能回答：

- 怎么判断 AI 诊断是否靠谱？
- 什么是固定评测集？
- 如何评估根因命中、证据引用和幻觉？

项目中的用法：

- 为支付超时、Redis 异常、数据库慢查询设置期望答案。
- 自动运行诊断并生成评测报告。
- 用评测结果改进 Prompt、Runbook 和工具调用策略。

## 建议学习顺序

1. Spring Boot CRUD、分层架构、DTO 和异常处理。
2. 故障事件和故障注入业务闭环。
3. 日志、指标、链路追踪的基本概念。
4. Spring Boot 调用 Python FastAPI。
5. Chroma + Runbook RAG。
6. 异步任务和任务状态机。
7. SSE 实时推送。
8. Function Calling 和工具网关。
9. Redis 缓存、限流、任务状态和 Stream。
10. HTTP 超时与 Resilience4j 重试、熔断和并发隔离。
11. Prometheus、Grafana 和 OpenTelemetry。
12. AI 诊断质量评测。
13. Docker Compose、Nginx 和项目展示。
