## 已确认并修复的问题

### 1. 失败工具被误计为 LLM 取证完成

严重度：高。`LlmAgentRuntime` 原先只记录工具名是否出现，不检查 Tool Gateway 返回状态。
五类必需工具中的任意一次 `FAILED` 都会被当成已经取证，模型可以直接提交缺少有效证据的
最终报告。

修复：只把 `status=SUCCESS` 的工具加入完成集合；失败工具必须在剩余步数内重试。新增测试
先复现首次 Runbook 失败仍被接受，再验证第二次成功后才能生成报告。

### 2. 同一任务的 SSE 订阅相互覆盖

严重度：高。发布器原先使用 `taskId -> SseEmitter`，页面刷新、重连或多标签页会让新连接
覆盖旧连接。旧连接无法收到终态，只能等待五分钟超时；历史运行日志中的重复订阅和
`AsyncRequestTimeoutException` 与该路径一致。

修复：改为 `taskId -> Set<SseEmitter>`，使用按 key 原子更新避免订阅/清理竞态。单条连接
失败只清理自身，终态向全部订阅者发送后逐一完成。新增同任务双订阅回归测试。

### 3. 进程重启后任务永久悬挂

严重度：高。任务状态在 MySQL 中持久化，但实际执行是进程内 `@Async`。进程退出后，旧的
`PENDING/RUNNING` 没有执行线程，也没有启动对账，会永久保持进行中并继续被页面恢复或
Redis 复用。

修复：新增单实例启动对账服务，把旧的未完成任务持久化为 `FAILED`，更新 Redis 快照并清理
复用索引和锁。这里故意不自动重放，以免重复生成诊断记录和工具审计。它不是多实例接管或
消息队列续跑能力。

### 4. 协作规则缺少仓库级稳定入口

严重度：中。协作方法散落在文档中，缺少对自动工程协作者直接生效的根级规则。

修复：新增根级 `AGENTS.md`，固化事实边界、单写入者默认、`MULTI_TASK=ON` 开关、修改约束、
验证命令和“未测不宣称”的完成定义。动态进度和一次性结果仍留在日期化报告中。

## 本轮未扩范围的风险

| 风险 | 当前判断 | 为什么没有在本轮直接改 |
| --- | --- | --- |
| 后端/Tool Gateway 没有身份、租户和 RBAC | 本地作品边界内已文档化；对外部署属于高风险 | 需要先确定身份源、服务间认证和租户数据模型，不能用临时 Header 冒充鉴权 |
| 直接访问 8080 时信任 `X-Forwarded-For` | 可伪造客户端 key，削弱限流 | 需要可信代理列表或网关强制入口；会改变部署合同 |
| Incident 输入和 LLM 报告缺少完整长度校验 | 超长输入/输出可能在数据库字段处失败 | 应统一定义 API、模型和表字段上限后一起实现，避免各层不一致 |
| 前端 SSE 出错后只做一次状态查询 | 瞬时断线且任务仍运行时不会自动恢复实时进度 | 需要明确退避、最大重试和轮询降级体验 |
| `@Async` 执行器没有显式容量/拒绝策略 | 高并发下可能形成不可控排队 | 需要先给出演示环境并发目标和过载语义 |
| `ddl-auto=update`、默认本地密码、Actuator 细节暴露 | 只适合本地演示 | 生产化需要迁移工具、Secret 管理和管理端点网络隔离 |
| CI 没有真实 Compose smoke | 单测和构建不能发现网络/启动顺序问题 | GitHub Runner 资源、镜像缓存和执行时长需要单独设计 |

## 2026-08-12 本地生产化补强与复验

本节是 8 月 10 日审计后的增量结果，不改写上面的历史判断。本轮只处理可以在本机给出
真实证据、且不需要外部身份源或生产凭证体系的项目。

### 已实现的本地安全边界

| 原风险 | 当前实现 | 本地边界 |
| --- | --- | --- |
| 信任任意 `X-Forwarded-For` | 限流只使用 socket 对端地址，客户端 Header 不再生效 | 生产代理后的真实用户 IP 仍需可信代理 allowlist |
| 输入/报告缺少完整长度限制 | Java DTO、Python Pydantic 和 Java 报告落库前校验统一限制文本、集合与映射大小 | 这是资源与数据合同保护，不代替身份鉴权 |
| SSE 瞬断后不继续恢复 | 前端关闭失效连接，按 500ms 至 5s 指数退避重连，并查询持久化任务终态 | 长时间离线仍以 MySQL 任务状态为准，不补发全部瞬时进度 |
| `@Async` 容量不明确 | 专用线程池核心 2、最大 4、队列 20，拒绝时 HTTP `503` 且任务落为 `FAILED` | 单实例进程内执行，不提供跨实例接管或续跑 |
| 后端宿主机暴露范围过宽 | Compose 默认绑定 `127.0.0.1`，并允许显式覆盖宿主端口 | 生产网络策略、TLS 和网关配置仍不在本地实现范围 |

### 仍需外部决策或生产基础设施

- 真实供应商 LLM 仍未配置 API Key，不能宣称真实模型 Tool Calling、Token 或延迟已验收。
- 身份、租户、RBAC 和服务间认证需要先确定身份源与数据隔离模型，未用临时 Header 伪造。
- 可信代理 allowlist 尚未实现；当前安全默认会让同一反向代理后的请求共享限流 key。
- 默认本地密码、`ddl-auto=update`、环境变量传密钥和 Actuator 暴露不构成生产凭证管理方案。
- 当前故障数据和可观测数据仍是本地可重复模拟源，不是生产日志、指标、Trace 或告警。
- 任务仍是单实例进程内执行。中断后明确失败而非续跑，不具备队列消费和多实例接管能力。
