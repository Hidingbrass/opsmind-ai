# 开发路线图

## 第 1 阶段：项目骨架

目标：创建一个可以运行的多服务项目骨架。

交付物：

- 根目录结构。
- Spring Boot 后端骨架。
- AI 服务骨架。
- 前端骨架。
- 包含 Redis、Chroma、数据库、后端、AI 服务、前端和 Nginx 的 Docker Compose。
- 健康检查接口。

验收标准：

- 所有服务可以在本地启动。
- `GET /api/health` 返回后端健康状态。
- `GET /ai/health` 返回 AI 服务健康状态。

## 第 2 阶段：故障事件核心功能

目标：先做出不依赖 AI 的业务闭环。

交付物：

- 故障事件实体。
- 故障状态：待处理、诊断中、已解决。
- 模拟故障注入接口。
- 三个场景对应的静态日志、指标和链路数据。

验收标准：

- 用户可以创建一条支付服务超时故障。
- 用户可以查询故障详情。
- 后端可以返回相关日志、指标和链路数据。

## 第 3 阶段：基础 AI 诊断

目标：让系统基于结构化故障上下文生成诊断结果。

交付物：

- AI 诊断 Prompt。
- Spring Boot 调用 AI 服务。
- 使用 SSE 流式返回诊断过程。
- 将诊断报告持久化到数据库。

验收标准：

- 用户点击“开始诊断”。
- 系统流式展示诊断过程。
- 最终诊断包含根因、证据和修复建议。

## 第 4 阶段：RAG 知识库

目标：把运维知识接入诊断流程。

交付物：

- 运维手册文档格式。
- 文档导入 API。
- 文本切分。
- Chroma 向量存储。
- 运维手册检索 API。

验收标准：

- 可以导入支付服务超时运维手册。
- AI 诊断会使用检索到的运维手册内容。
- 最终报告包含引用来源标题。

## 第 5 阶段：Function Calling

目标：让 AI Agent 自己决定调用哪些诊断工具。

交付物：

- 工具定义。
- 工具调用执行器。
- 工具调用时间线。
- 危险操作保护机制。

验收标准：

- Agent 能调用日志、指标、链路和运维手册检索工具。
- 前端能展示每一次工具调用。
- 重启或回滚等操作必须由人工确认。

## 第 6 阶段：Redis 工程化

目标：让 Redis 的使用在面试中讲得清楚、站得住。

交付物：

- 诊断结果缓存。
- 请求限流。
- 任务状态存储。
- 可选：Redis Stream 事件队列。

验收标准：

- 重复诊断同一故障时可以命中缓存。
- 页面刷新后仍能恢复诊断任务进度。
- 过于频繁的诊断请求会被友好拒绝。

## 第 7 阶段：控制台和演示打磨

目标：让项目视觉上足够清晰、有冲击力。

交付物：

- 故障控制台。
- 故障注入面板。
- 诊断时间线。
- 报告页面。
- 架构图。
- 演示说明文档。

验收标准：

- 招聘方或面试官可以在 3 分钟内理解项目价值。
- 技术面试官可以围绕架构、Redis、RAG 和 Function Calling 继续追问。

## 第 8 阶段：部署和简历材料

目标：让项目达到作品集可展示状态。

交付物：

- Nginx 反向代理。
- Docker Compose 一键启动。
- GitHub Actions 构建检查。
- API 文档。
- 简历项目描述。
- 面试讲解脚本。

验收标准：

- 新机器拉取代码后，可以按照文档在本地启动。
- README 能解释架构、演示步骤和技术亮点。
